# iOS 听歌识曲

- 入口：顶部搜索旁的波形按钮。
- 麦克风：开始识别时调用 `getUserMedia`，由系统请求麦克风权限；不是启动应用就录音。
- 系统声音：用户点击系统广播按钮并确认开始，然后切换到播放音乐的 App。采集约 8 秒音频后自动结束广播，返回 SPlayer 后计算指纹和查询结果。
- 不采集麦克风样本，不保存或处理屏幕画面。受保护媒体可能无法采集。
- 若用户停止广播、取消识别或超时，释放采集资源；临时 PCM 在读取后删除，异常退出遗留文件在下次识别时清理。

## 签名与打包

构建脚本自动增加 `RecognitionBroadcast.appex`，并为主应用和扩展声明同一个 App Group：
`group.top.imsyy.splayer-next.ios.recognition`。

重签名时必须同时签主应用和广播扩展，为二者配置有效的 App Groups entitlement 和 provisioning profile。运行时读取两者实际 Mach-O 签名中的共享组交集，优先使用原始组，否则按固定顺序选择共同授权的组，兼容全能签改写组名。没有共同授权时明确报错，不使用描述文件中的未签入权限。

采样文件只保存在共享容器的 `SPlayerRecognition/<主应用 Bundle ID>/` 子目录，不清理共享组根目录或其他应用的数据。仅给主应用签名、移除扩展或删除共享组权限，仍会使机内识曲不可用。

IPA 检查会验证扩展已嵌入；无签名 IPA 构建成功不代表设备上的广播和共享容器可用。

## 实机验收（待执行）

### 重采样试听排查

每次系统音源采集完成后，会将实际指纹输入保存至“文件 → 我的 iPhone/iPad → SPlayer → 听歌识曲采样”。`试听.wav` 为 8 kHz 单声道 16 位 PCM，`原始浮点.wav` 保留未量化的 Float32 样本，`采样信息.json` 记录时间、输入采样率及声道数、格式变化次数、输出时长、RMS、峰值和近静音样本数。导出不做额外重采样或增益处理。

仅保留最近一次成功导出的同名文件，识曲是否命中不影响保存。若中途取消、采集失败或导出失败，需核对 JSON 时间戳，避免试听到上一次结果。这些文件包含实际捕获的声音，可由用户在“文件”中删除；不会自动上传。排查时将两个 WAV 和 JSON 一并分享。

- 首次麦克风授权、拒绝后重试、设置中撤回权限。
- 系统选择器显示 SPlayer，确认开始后切换其他 App 播放音乐，返回后展示识别结果。
- 耳机连接、无音频、受保护媒体、广播暂停/停止、取消选择器、连续重复识别。
- 锁屏、切后台超过超时、强制退出后重新开始；确认无持续录音、残留广播或旧结果串入。
- 主应用与广播扩展内存检查：采样上限为 64000 个 Float，结束后释放；验证重复会话不会持续增长。

当前开发机为 Windows，iOS 原生编译、签名和上述实机流程需在 macOS / iPhone 完成，不视为已验证。
