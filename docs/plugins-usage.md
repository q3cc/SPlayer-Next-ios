# 插件使用指南

SPlayer-Next 支持通过插件扩展**音源**（解析歌曲的播放地址）与**控制**（联动播放状态、反向控制播放）。本文面向最终用户，介绍如何安装、启用与管理插件。想自己写插件，见 [插件开发](/plugins/)。

## 打开插件管理

**设置 → 插件管理**。每个已安装插件以卡片展示：名称、版本、作者、运行状态与支持的音源。

## 安装插件

两种方式，效果相同：

- **本地导入**：选择一个 `.js` 脚本文件。
- **在线导入**：粘贴一个指向 `.js` 脚本的 `http(s)` 链接（如 GitHub / Gitee 的 raw 地址）。

部分作者会以 `gz_` 前缀分发压缩脚本，SPlayer-Next 会**自动识别并解压**，无需额外操作。

## 启用 / 禁用 / 卸载

- 新安装的插件会**自动启用**。
- 在卡片上可随时启用或禁用插件；可同时启用多个插件（含多个音源），当多个插件支持同一音源时，由 SPlayer-Next 按优先级自动选用。
- 控制插件若声明了设置项，可在卡片上打开**设置**进行配置。
- **卸载**会删除脚本及其本地数据，且不可恢复。

状态徽章：**已导入**、**正在加载**、**可用**、**加载失败**（卡片下方会显示原因）、**已禁用**。导入成功只表示脚本已保存；需要联网初始化的脚本会保持加载状态，完成初始化后才显示可用。

## 兼容 lx 插件

SPlayer-Next 兼容 [lx-music-desktop](https://github.com/lyswhut/lx-music-desktop) 的 user_api 脚本，多数公开的 lx 脚本可直接导入使用。若脚本用到了不常见或较新的 lx 接口，可能会加载失败。

### iOS / Android 自定义音源

在 **设置 → 插件管理** 选择「本地导入」或「在线导入」。在线导入需要 HTTPS 脚本直链，不是 GitHub 仓库首页或文件预览页；本机调试地址可使用 HTTP。

[pdone/lx-music-source](https://github.com/pdone/lx-music-source) 收录了多个独立脚本，可从其 README 获取各脚本直链。应用不内置这些脚本，也不会自动安装它们。请自行核实来源与使用要求。

- 当前歌曲平台支持网易云、QQ 音乐与酷狗；脚本额外声明的平台不会自动增加到搜索列表。
- 可同时启用多个音源：优先使用官方完整音源，失败后按已配置的插件顺序尝试，最后才考虑已允许的试听片段。
- 脚本显示「可用」表示已完成加载，不代表其第三方服务、所有歌曲或所有音质都能使用。
- LX 脚本的更新通知不会自动替换代码。点击「查看更新」，下载新版脚本后重新导入；同一身份的脚本会保留启用状态和设置。
- 移动端向脚本报告 `lx.env = "mobile"`，协议版本保持 `2.0.0`。本次兼容不包含 Siri 在后台执行自定义脚本。

若显示加载超时，可能是脚本的初始化服务未响应；若播放时提示密钥无效、限流或服务不可用，需要向音源作者确认。重新导入无法修复第三方服务本身。

## 常见问题

**导入后状态显示「加载失败」？**
查看卡片下方的错误信息，通常是脚本本身的语法 / 运行错误，或脚本声明的 API 级别高于当前版本（需等待应用升级）。

**插件崩溃会影响应用吗？**
不会。插件运行在独立沙箱中，崩溃会被隔离并自动恢复，不影响主程序。

**插件请求很慢？**
插件的网络请求会遵循系统代理，速度取决于目标接口与网络状况。
